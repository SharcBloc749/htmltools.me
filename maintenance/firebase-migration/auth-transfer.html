Transfer Firebase accounts

website-encryption-htmltools → general-database-4cb1c

Run through the local launcher, not on your public website. Back up both projects first. Pause destination sign-ups until finished. The source is read-only; the destination must have zero accounts. This tool transfers all source accounts without spam filtering. Account removal requires a separate UID-by-UID review.

1. Choose admin keys and preview

For each Firebase project: Project settings → Service accounts → Firebase Admin SDK → Generate new private key. Save the JSON privately, outside GitHub. Select the correct files below. They are sent only to the local server, held in its memory, and used to contact Firebase. The server does not save them to disk.

The source account needs permission to list users and read password hashes (firebaseauth.configs.getHashConfig). The destination account needs import/list-user permissions. Do not weaken database rules; they are unrelated to this transfer.

2. Enter OLD project password hash settings

Old project's Authentication → Users → ⋮ → Password hash parameters. This tool supports Firebase SCRYPT only. Enter the values, not the surrounding hash_config block or trailing commas.

Incorrect hash settings can import accounts whose old passwords no longer work. Use only the old project's exact settings. Advanced MFA accounts are blocked rather than silently losing factors.

3. Transfer

Import writes are not a single atomic transaction. If an error occurs after transfer starts, some accounts may already exist in the destination. Do not delete them or blindly retry: inspect the destination first.

Open this page using the private URL printed by START-AUTH-TRANSFER.cmd. Opening this HTML directly will not transfer accounts.

After transfer

  1. Enable the same email/password, Google and other sign-in providers in the new project. Configure authorized domains and email-action URLs.
  2. Test an existing email/password account and provider login. Compare the old and new UIDs, disabled status and custom claims.
  3. Migrate database data separately with the original UIDs. This tool does not copy chats, artwork, files or database rules.
  4. Update external workers to validate new-project tokens. Users must sign in again.
  5. Close this server with Ctrl+C. Delete downloaded key files when no longer needed and revoke those temporary service-account keys in Google Cloud/Firebase settings.

Other settings, tenant users, MFA, sessions and provider secrets are not migrated. The default Auth user pool is copied, not a complete project backup.
