The htmltools.me AI API

An OpenAI-compatible chat completions gateway running on Cloudflare Workers. Two providers are reachable: the shared Workers AI free pool and, if you connect one, your own Groq key. No other provider, model or billing account is wired up.

Base URL https://htmltools-me-ai-api.bozhetarnikmatthew.workers.dev/v1

Getting started

  1. Sign in at htmltools.me/AI-API/Dashboard with an AI Playground account (Firebase project general-database-4cb1c).
  2. Create a key. It is shown once — copy it then.
  3. Use https://htmltools-me-ai-api.bozhetarnikmatthew.workers.dev/v1 as the base URL and the key as the API key.
  4. Pick a model from the allowlist. auto works if you do not care which one runs.
minimal request
curl https://htmltools-me-ai-api.bozhetarnikmatthew.workers.dev/v1/chat/completions \
  -H "Authorization: Bearer ht-YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "@cf/meta/llama-3.1-8b-instruct",
    "messages": [{"role": "user", "content": "Hello"}]
  }'

For tools and agents

  • llms.txt — a compact plain-text contract (base URL, models, limits, error codes) written to be pasted into an AI tool or agent.
  • openapi.json — OpenAPI 3.1 description of the two `/v1` endpoints, importable by Postman, Insomnia or a code generator.

OpenAI SDK

python
from openai import OpenAI

client = OpenAI(
    base_url="https://htmltools-me-ai-api.bozhetarnikmatthew.workers.dev/v1",
    api_key="ht-YOUR_KEY",
)

stream = client.chat.completions.create(
    model="@cf/meta/llama-3.1-8b-instruct",
    messages=[{"role": "user", "content": "Write one sentence about the sea."}],
    stream=True,
)
for chunk in stream:
    print(chunk.choices[0].delta.content or "", end="")

Authentication

Every /v1 request needs a bearer key:

Authorization: Bearer ht-3jhnnuj2tgq8m4xwv7b2n5r0kd9fcs
  • Keys start with ht- followed by 30 lowercase characters.
  • The first 13 characters are the public key id (ht-3jhnnuj2tg) used in the dashboard and support.
  • Only a salted SHA-256 hash is used to authenticate requests. If the operator has enabled escrow (the recommended setting, and the one used on the live gateway), an AES-256-GCM copy is also kept in the private roster so the owner can view the key again after re-entering their password.
  • Revocation is immediate — the gateway checks a strongly consistent store on every request.
Keys are bearer credentials. Do not put them in client-side JavaScript that ships to strangers, public repos, or screenshots. Anyone who has the key can spend your share of the pool.

POST /v1/chat/completions

Accepts an OpenAI chat body and returns an OpenAI chat response. Parameters outside the table are ignored rather than silently forwarded to a provider.

Streaming

Set "stream": true to receive text/event-stream. Workers AI chunk events are translated into OpenAI chat.completion.chunk events. Groq responses are proxied as-is with stream_options.include_usage enabled.

events
data: {"id":"chatcmpl-…","object":"chat.completion.chunk","choices":[{"index":0,"delta":{"role":"assistant","content":""},"finish_reason":null}]}

data: {"id":"chatcmpl-…","object":"chat.completion.chunk","choices":[{"index":0,"delta":{"content":"Hello"},"finish_reason":null}]}

data: {"id":"chatcmpl-…","object":"chat.completion.chunk","choices":[{"index":0,"delta":{},"finish_reason":"stop"}]}

data: [DONE]

Tool calling

Tool calling is allowlisted per model. Workers AI's Llama 3.1 8B and 3.3 70B are marked tool-capable in this gateway, as are the Groq models. A tool-capable request is forwarded with tools and tool_choice; the reply carries tool_calls on the assistant message and finish_reason: "tool_calls".

request
{
  "model": "@cf/meta/llama-3.3-70b-instruct-fp8-fast",
  "messages": [{"role": "user", "content": "What is the weather in Halifax?"}],
  "tools": [{
    "type": "function",
    "function": {
      "name": "get_weather",
      "description": "Current weather for a city",
      "parameters": {
        "type": "object",
        "properties": { "city": { "type": "string" } },
        "required": ["city"]
      }
    }
  }],
  "tool_choice": "auto"
}
Live behaviour depends on the upstream model. Non-streaming tool calls are covered by the gateway's tests with mocked providers; the exact willingness of a given Workers AI model to emit tool calls must be verified after deployment. Streaming tool-call deltas are forwarded when the provider emits them and are not part of the tested contract.

What "budget exhausted" actually means

  • Neurons are reserved before the provider call, so concurrent requests cannot overshoot the daily cap.
  • When the pool is empty, free-pool models stop with a 429. There is no fallback to a paid provider — the request simply fails.
  • The pool resets at 00:00 UTC. Your own Groq key is unaffected by the shared pool.
  • Counters are checkpointed every 30 seconds; the configured budget keeps headroom for that window.

Your own Groq key (BYOK)

  1. Create a key at console.groq.com (free plan is fine).
  2. In the dashboard, open “Provider keys”, confirm your password, and paste the key.
  3. The gateway validates it with a non-inference GET /models call to Groq, then stores an AES-256-GCM ciphertext.
  4. Requests for Groq model ids now use your account. Remove the key any time with “Disconnect”; the ciphertext is deleted immediately.

Where the encryption secret lives: in Cloudflare Worker secrets as BYOK_ENCRYPTION_KEY. It is never sent to a browser, never written to the repository and never written to the private roster. The AES key is derived with HKDF-SHA-256 using the Firebase uid as context, so a ciphertext moved to another account will not decrypt. Rotating the secret makes existing ciphertexts unreadable — users must reconnect their keys.

Your Groq key is used only for your own requests. The operator cannot see it in the dashboard; the roster stores ciphertext. Groq's own terms and rate limits apply to those calls.

HTSilo

POST /htsilo/chat powers the green assistant on these pages. It requires a Firebase ID token, takes {"messages": [...]}, and returns {"reply": "...", "remaining": 14, "model": "..."}. The system prompt, model and 320-token cap are fixed server-side; callers cannot override them. Limits: 4 messages per minute and 15 per day per account, all inside the shared pool.

Privacy & data handling

  • Not stored: prompt or completion text, in any database, the Durable Object, or the GitHub roster.
  • Stored: request counts, token estimates, model id, key id, timestamps and byte counts, kept for accounting and abuse control.
  • Key material: a salted SHA-256 hash for every key, plus — when escrow is enabled — an AES-256-GCM ciphertext in the private roster. The plaintext is never returned to any browser except after the owner re-authenticates (or the operator uses the admin passphrase).
  • Logged: structured metadata lines (event, model, key id, latency, token counts). The code never passes message content to the logger.
  • Sent to providers: the full prompt for the request. Free-pool prompts go to Cloudflare Workers AI; Groq prompts go to Groq using your key.
  • Third-party policies: Cloudflare and Groq process that data under their own terms. If your prompts are sensitive, use your own provider key and review that provider's data policy.

What this gateway is not

  • Not an OpenRouter clone: there is no upstream paid routing, no model catalogue beyond the allowlist, and no billing.
  • No /v1/completions, /v1/embeddings, /v1/responses, image, audio, files, batches or fine-tuning.
  • No image input (vision), even on models that support it upstream, because it would let one request consume a large share of the pool.
  • No guaranteed uptime and no SLA. The free pool is a courtesy and stops when the daily allowance runs out.
  • No cross-account sharing of Groq keys, ever.
